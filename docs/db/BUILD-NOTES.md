## 2026-11-17 — Credit window protocol

- Working on feat/db-v1-runtime from merged main. No further merges are authorized.
- Stream open requests offer 16 credits; the peer explicitly selects 16 in its opened response. Missing negotiation retains one frame. Each ordered acknowledgement returns exactly one credit. The sender waits for all outstanding credits before completing a write, preserving EOF ordering.
- Receiver buffering is bounded by its 64 KiB drain threshold plus the 16 outstanding 32 KiB frames. Invalid sequence, oversized frames and invalid acknowledgements close the stream. Credits held behind slow stdout are also held for subsequent stderr, preserving acknowledgement order.
- Added protocol unit tests and a measured 2 MiB/100 ms RTT comparison (6.47s versus 0.41s). Real Docker two-node and reconnect evidence remains a separate gate before capability advertisement.
- The repository has no configured formatter/linter. Use Prettier with existing single-quote/no-semicolon conventions and pinned Oxlint 1.57.0 for these files at each milestone, alongside tsc and Go checks. Both tools passed for the relay and tests.

## 2026-11-17 — Encrypted backup worker

- Reused the existing operation lease and encrypted intent; the backup row and operation are committed in one transaction and share the generated backup ID. Replaying an idempotency key returns the same operation even if the database has since changed state. A completed artifact is retained if lease completion is lost, so reconciliation can finish without re-uploading it.
- Manual Postgres backups currently use `pg_dump --format=custom`; this intentionally captures a portable logical dump rather than the engine plugin's WAL-G base backup. Durable Redis snapshots use `redis-cli --rdb`. Cache-mode Redis remains ineligible because it has no persistent recovery contract.
- The control plane encrypts during the stream with AES-256-GCM and a per-backup HKDF-derived key. The encrypted object begins with a fixed format marker and nonce and ends with the GCM tag. An 8 MiB multipart uploader keeps a bounded buffer and follows stream backpressure. The worker reads the completed object back and hashes it before setting `verifiedAt`; the manifest checksum covers the entire encrypted object. Upload failure aborts the multipart session; verification failure removes a completed object before retry.
- Redis `--rdb /dev/stdout` was rejected by a real run because redis-cli calls `ftruncate` and `fsync`. The Go agent now substitutes a generated path under `/tmp`, streams only that file through the Docker archive endpoint, validates the archive entry, and removes the file through an internal fixed `rm` invocation. The path is session-generated, not caller-controlled.
